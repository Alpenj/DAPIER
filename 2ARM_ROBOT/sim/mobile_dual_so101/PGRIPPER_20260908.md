# 오른팔 NORMA PGripper 반영 — SIM 검증 기록

record_id: DAPIER-2026-09-08-right-pgripper-simulation

나는 오른팔을 [NORMA PGripper](https://github.com/norma-core/norma-core/tree/b935fc4b887e576538921b15630a30db22759ec8/hardware/pgripper)로
교체했다. 왼팔은 아직 기본 SO-101이며 나중에 양팔 모두 바꿀 예정이다. 팔에 달려 있던
손목 카메라 세트는 그대로 유지한다. 이번 코드는 이 구성을 MuJoCo에서 확인하는 단계다.
실물 모터·카메라를 열거나 calibration을 바꾸는 명령은 실행하지 않았다.

## 찾은 원본과 적용 범위

PGripper 폴더에는 STL/STEP이 있고 독립 URDF는 찾지 못했다. 같은 저장소의
[ElRobot simulation URDF](https://github.com/norma-core/norma-core/blob/b935fc4b887e576538921b15630a30db22759ec8/hardware/elrobot/simulation/elrobot_follower.urdf)에서
base·motor·gear·jaw 2개로 된 subtree를 찾았다. 해당 다섯 STL, 원본 URDF와 hardware
Apache-2.0 라이선스를 `assets/norma_pgripper/upstream/`에 원형 보존하고 SHA-256을 기록했다.
전체 ElRobot의 나머지 링크 mesh는 복사하지 않았으므로 그 URDF 자체는 전체 로봇 실행용이 아니다.

인쇄용 jaw와 simulation jaw를 강체 정렬해 비교하니 simulation vertex의 최대 차이는
약 0.000036mm였다. 삼각형 수는 다르지만 확인한 기하학적 특징은 일치했다.
이번 것은 **공식 SO-101용 URDF를 발견한 결과가 아니라 원본 형상을 옮긴 adaptation**이다.
조원에게 SO-101 장착 URDF를 받으면 실제 체결 위치·회전·카메라 frame부터 대조한다.

| 구성 | 왼팔 | 오른팔 | 용도 |
| --- | --- | --- | --- |
| `stock` | 기본형 | 기본형 | 기존 녹화·ACT·회귀 검사 보존 |
| `right` | 기본형 | PGripper | 현재 교체 상태의 SIM |
| `both` | PGripper | PGripper | 향후 양팔 교체의 SIM 미리보기 |

기존 mobile/compact/tabletop builder는 `grippers=`를 받되 stock 기본값을 유지한다.
새 `pgripper_sim.py`는 right가 기본이다. 기존 LeRobot fork·원본 XML/STL·ROS URDF는
수정하지 않고 불러온 MuJoCo spec에서만 교체한다. RoboTwin/SAPIEN 실행기와 과거 ACT는
이번에 새 그리퍼로 전환하지 않았다. 과거 성공 결과도 PGripper 결과로 바꾸어 읽지 않는다.

## 기구·단위·충돌

좌 6축→우 6축, actuator 총 12개는 유지한다. 교체한 팔마다 passive prismatic joint
2개와 joint equality 2개가 추가된다. 물체를 붙이는 weld는 없다.

```text
q_open = 2.2028 - upstream_motor_angle  [rad]
jaw travel per side = 0.0115 × upstream_motor_angle  [m]
inner-face gap ≈ 0.000368878 + 0.023 × q_open  [m]
```

`data.ctrl`의 새 집게 값은 opening-positive rad이며 0은 명목 닫힘, 2.2028은 최대 열림이다.
정규화 정책 경계의 0..1과 혼동하지 않는다. 이 SIM 좌표를 실물 tick이나 예전 녹화의
0..100에 그대로 대응하지 않는다. `recorded_to_sim`/`sim_to_recorded`는 PGripper 모델에
기본형 녹화를 넣으면 거부한다. 향후 정책 연결 때 새 그리퍼·보정·dataset·checkpoint
revision을 명시적으로 묶어야 하며 범용 action normalizer만으로 호환성을 판단하지 않는다.

원본 URDF 기준 총 이동량은 **50.6644mm**다. 최대 개구는 약 **51.0333mm**, 명목 닫힘에도
약 **0.3689mm**가 남는다. README의 54mm는 광고된 총 travel이므로 이 값을 맞추려고
CAD나 기어 비율을 임의 확대하지 않았다. 실제 개폐 끝점과 장착 방향은 별도 측정한다.

손끝 접촉은 distal CAD vertex의 convex hull로 만들어 가늘어지는 윤곽을 보존한다.
첫 사각형 proxy는 실제 tip보다 한쪽으로 약 8.125mm 넓어지는 문제가 있어 교체했다.
housing은 box이며 손가락 전체·rack·gear tooth 접촉은 모델링하지 않는다. 따라서 전체
충돌 정확도나 파지 성능은 미검증이다. 공통 충돌 guard는 교체된 housing과 양쪽 pad를
필수로 검사하고 하나라도 비활성화하면 거부한다. 기본형의 기존 검사도 유지한다.

장착은 horn 중심·축 정렬 가정이다. TCP는 양쪽 내측 면의 중간점으로 개폐 중 위치가
변하지 않는다. 원본 질량·관성을 변환하되 0으로 제공된 작은 gear 관성만 CAD bbox로
근사했다. 마찰·gain·effort·damping·실제 mount 오차는 동특성 식별값이 아니다.
기존 camera 상대 pos/quat/FOV는 유지했지만 새 그리퍼의 가림·실측 외부 보정은 확인 전이다.

## 재현과 확인한 결과

기존 MuJoCo·LeRobot·Arrow·Pillow 환경을 사용하며 새 의존성은 추가하지 않았다.
아래 `python`은 그 환경의 실행 파일로 바꾸고 XML은 인접 assets가 있는 기존 기본형을 지정한다.
출력 경로는 존재하지 않는 새 디렉터리를 쓴다.

```bash
export DAPIER_SO101_MJCF=/absolute/path/to/so101_new_calib.xml
MUJOCO_GL=egl python 2ARM_ROBOT/sim/mobile_dual_so101/pgripper_sim.py \
  --output /tmp/new-pgripper-right
MUJOCO_GL=egl python 2ARM_ROBOT/sim/mobile_dual_so101/pgripper_sim.py \
  --grippers both --output /tmp/new-pgripper-both
python -m unittest discover -s 2ARM_ROBOT/sim/mobile_dual_so101/test \
  -p test_pgripper.py -v
```

`--viewer`를 추가하면 SIM 전용 native Control panel을 최대 5분 연다. GUI를 사용할 때는
설치 환경의 GUI backend를 사용한다. 자동 실행에서는 GUI를 열지 않고 EGL로 렌더했다.
MJCF는 mesh의 절대 경로를 참조하므로 자산 폴더를 옮기면 다시 생성한다. MJCF 안의
`home` keyframe을 선택해야 보고서의 시작 자세가 된다. `MjData` 기본값만 쓰면 같은 자세가 아니다.

- MuJoCo **3.8.1·3.3.7**에서 새 통합 검사 2개 모두 통과했다. stock/right/both의
  12축 계약, passive coupling, 양팔 개폐, camera 보존, 저장 MJCF 재열기를 확인했다.
- 3.8.1에서 기본 mobile 14개·compact 12개·policy 4개·collision guard 10개가 통과했다.
- 기본형 `test_tabletop_physics.py`도 다시 실행했다. 책상 집기·3초 유지, 처음부터
  접촉 제거 시 획득 실패, 획득 후 접촉 제거 시 낙하가 통과했다. 기존 결과를 새 그리퍼
  결과로 바꾸지 않고 `recording/simulation/20260908/stock-after-pgripper/`에 따로 남겼다.
- 새 개폐 실행은 초기화 한 번 뒤 `data.ctrl`과 `mj_step`만 사용했다. 1,500 step 동안
  warning 0·유한 상태였고 오른팔 장면은 `nq=21, nv=20, nu=12, neq=2`다.
- right 구성의 왼팔 body pose·질량·관성과 control range는 기본형과 같았다.
  tabletop camera pos/quat/FOV와 compact camera pos/quat도 같았다.
- 새 폴더에 MJCF·열림/닫힘 PNG·`report.json`을 생성하고 MJCF를 다시 불러왔다.
  PNG는 **pose-only**다. 물리 trace도 물체를 집지 않는 개폐 smoke이며 파지 성공 근거가 아니다.

실행 결과는 비공개 `recording/simulation/20260908/pgripper-right-final/`과
`pgripper-both-final/`에 두었다. `sim_to_real_valid=false`, `grasp_success_verified=false`,
`hardware_execution=false`를 유지한다. 다음은 최종 장착 확인→카메라 보정→새 개폐/TCP
측정→집기·접촉 제거 대조→새 데이터와 정책 검증 순서다.

수정 전 커밋 `834247c94de62b826b6c4f67792fdd3c2dd11c75`와 다음 archive를
비공개 `recording/backups/20260908-before-pgripper/`에 따로 보존했다.

`MANIFEST.json`에 원래 경로와 archive SHA-256을 기록하고 gzip 무결성을 확인했다.
기존 원시 dataset·개인 calibration은 제자리에 보존하며 공개하거나 덮어쓰지 않았다.
복구할 때는 archive를 **새 디렉터리**에 풀어 확인하고 현재 checkout이나 개인 보정에
바로 덮어쓰지 않는다. source archive는 private dataset/calibration 백업을 뜻하지 않는다.
