# PGripper 형상을 RoboTwin/SAPIEN으로 옮겨 데이터 생성

record_id: DAPIER-2026-09-09-robotwin-pgripper-data

나는 최신 MuJoCo의 양손 NORMA PGripper 형상과 손목 카메라 배치를
RoboTwin의 Base_Task 장면에 옮겨, 왼손 집기 → 오른손 인계 → 오른손 내려놓기를 실행했다.
10회 모두 물리 동작과 저장 데이터 검사를 통과했다. 기존 기본형 집게의 녹화나
성공 데이터를 새 그리퍼 데이터로 재해석하지 않았다.

| 이번에 직접 확인한 결과 | 값 |
| --- | ---: |
| 성공·검증 에피소드 | 10 / 10 |
| 관측 프레임 / RGB 이미지 | 21,339 / 64,017 |
| 물리 계산 | 426,678 step, 총 853.356초 |
| 최대 접촉 관통 / 패드 법선 힘 | 0.0577mm / 4.249N |
| 최대 jaw 연동 오차 | 0.1091mm |
| 양 엔진 FK 대조 | 20개 링크 × 8개 자세, 최대 위치 차이 0.000163mm |
| 저장 규모 | 약 2.51GB, 원시 데이터는 로컬 보관 |

seed 0은 기준 장면, seed 1–9는 블록 중심 XY를 각각 ±1mm, yaw를 ±1° 안에서 바꾼다.
블록은 4cm·20g 자유 강체다. 이 작은 변화의 성공률을 넓은 작업 공간이나 다른 물체의
성공률로 해석하지 않는다.

## 코드와 재실행

- export_pgripper_reference.py: MuJoCo에서 좌표·축·joint ref·질량·관성·충돌/시각 mesh·
  카메라를 추출한다. MuJoCo의 전체 작업도 다시 실행해 성공한 IK 경유점을 보관한다.
- pgripper_collect.py: RoboTwin Base_Task의 장면과 SAPIEN articulation/tendon을 사용한다.
  추출한 경유점과 **SAPIEN에서 측정한 접촉**으로 동작하며 HDF5·MP4를 저장한다.
- validate_pgripper.py: 저장 파일만 읽어 시간 정렬, 매 물리 스텝 접촉, 전체 JPEG·깊이·
  영상 프레임을 별도로 검사한다.

이번 실행 환경은 export 쪽 MuJoCo 3.3.7, 수집 쪽 Python 3.10·SAPIEN 3.0.0b1이다.
기존 NumPy·SciPy·OpenCV·h5py와 로컬 RoboTwin 런타임을 사용했다.
MuJoCo와 RoboTwin의 Python 환경을 합치거나 새 의존성을 설치하지 않았다.
Base_Task.setup_scene의 dapier_ 장면용 기본 shader 패치가 있는 기존 런타임을 사용한다.

아래 변수는 자신의 실행 파일·최신 PGripper MuJoCo 소스·기본 SO-101 XML·RoboTwin
runtime·새 출력 경로로 지정한다. MJ_SOURCE에는 pgripper.py와 pgripper_handover.py,
관련 assets가 필요하다. 이 exporter가 그 MuJoCo 변경까지 설치하는 것은 아니다.

```bash
"$MJ_PY" -B 2ARM_ROBOT/robotwin/export_pgripper_reference.py \
  --source "$MJ_SOURCE" --model "$SO101_XML" --output "$OUTPUT/reference"
"$SAPIEN_PY" -B 2ARM_ROBOT/robotwin/pgripper_collect.py \
  --reference "$OUTPUT/reference" --runtime "$ROBOTWIN_RUNTIME" \
  --output "$OUTPUT/episode_000" --seed 0 --record
"$SAPIEN_PY" -B 2ARM_ROBOT/robotwin/validate_pgripper.py "$OUTPUT/episode_000"
```

출력 폴더는 새 경로여야 한다. 같은 명령에 다른 --seed와 --output을 지정해 추가 수집한다.
--fk-only는 좌표 대조만 실행한다. 실제 모터·ROS 연결은 사용하지 않는다.

## 그리퍼 연동과 실패 검사

모터 명령은 opening-positive 0..2.2028rad다. 각 jaw의 이동량은
±0.0115 × (2.2028 − motor_angle) m이며, 두 엔진에서 motor ref까지 반영한다.
각 side의 gear와 두 jaw를 native fixed tendon으로 연결하고, 실행 중 jaw 위치를 직접 덮어쓰지 않는다.

처음에는 tendon 힘 계수에 거리/각도 비율의 역수를 넣어 작은 접촉에도 모터가 버티지 못했다.
힘 계수를 constraint gradient에 맞추면 모터의 반력 단위가 0.0115Nm/N이 된다.
PhysX가 위치 계수와 힘 계수를 별도로 받는다는
[NVIDIA API 설명](https://nvidia-omniverse.github.io/PhysX/physx/5.1.2/_build/physx/latest/class_px_articulation_tendon_joint.html)과
[동역학 식](https://nvidia-omniverse.github.io/PhysX/physx/5.6.1/_downloads/8dfa0dc4fd04a98c3c836b4564801277/SDK_Tendon_Dynamics.pdf)을
대조했다. 사용한 stiffness 100,000, damping 20은 SIM 근사치이며 실측 기구 강성은 아니다.

양쪽 패드 각각 1N 이상을 연속 0.33초 확인한 뒤에만 파지로 인정한다.
운반 중 0.3N 미만의 접촉 상실, 패드 10N 초과, 1mm 초과 관통, 팔 간/자체/움직이는
팔과 테이블의 충돌, 0.3mm 초과 jaw 연동 오차를 거부한다.
오른손 단독 공중 유지 3초, 놓기 전 테이블 지지 0.2초, 놓은 뒤 양손 접촉 없는
테이블 정지 3초를 확인한다. 모터 제한은 팔 3.35Nm·집게 2.94Nm다.

--disable-recipient-contact는 받는 손 접촉을 끄고 인계 전 timeout으로 종료 코드 2가
나와야 한다. --drop-recipient-contact는 주는 손을 연 직후 받는 손 접촉을 끄며
다음 물리 스텝에서 중단돼야 한다. 이 두 대조 실행에서도 성공으로 기록되지 않았다.
각 실행의 source-pgripper_collect.py와 해시를 남긴다.

## 데이터 경계

HDF5 schema는 dapier.pgripper.sapien.v1이다.

| 경로 | 의미 |
| --- | --- |
| observation/state, action | 좌 6축 → 우 6축, 팔 rad·집게 0..1 |
| observation/state_rad, action_rad | 같은 표본의 전체 모터 rad |
| observation/images/* | 상부·좌우 손목 RGB, 320×240 JPEG |
| observation/depth_m | 상부 카메라 float32 metric depth, 무효 0 |
| timestamp_s, physics_step | 25Hz 관측 시간과 대응하는 500Hz step |
| expert/action_rad | 실제 적용한 모든 2ms 관절 명령 |
| expert/*500hz* | 매 step 측정 상태·접촉·블록 pose·단계 |
| camera_metadata/* | intrinsics, local/world 행렬과 좌표계 표기 |

관측은 해당 명령 **이전** 상태다. 25Hz의 action은 다음 20개 물리 명령 중 첫 명령이며,
그 구간 전체 명령은 expert/action_rad에 있다. 단일 명령을 40ms 유지한 녹화로 읽으면 안 된다.
검증기는 관측과 이전 step의 측정 상태, frame action과 해당 step 명령이 정확히 맞는지 검사한다.
첫 접촉 표본은 아직 물리 계산 전이므로 contact_valid=false와 NaN으로 표시한다.
블록 정답 pose·접촉·단계는 expert 그룹에 분리하며 정책 입력으로 섞지 않는다.

## 아직 확인하지 못한 것

이것은 RoboTwin Base_Task + SAPIEN에서 실행한 고정 장면 IK·가상 접촉 expert다.
위 인계 데이터는 RoboTwin의 CuRobo 수집기, 자체 학습 정책, 카메라 기반 visual servo나 실물 성공이 아니다.
기존 LeRobot 포맷이나 기본형 집게 checkpoint와 자동 호환된다고 하지 않는다.

형상은 MuJoCo와 같은 housing box·손끝 convex hull 근사다. rack·gear tooth·카메라
브래킷 전체 충돌, 실물 장착 오차·카메라 보정·마찰·모터 동특성은 미검증이다.
특히 PhysX 접촉 해석·마찰 결합과 MuJoCo의 torsional friction은 동일하지 않다.
실물 출력 비율을 Nm나 패드 N으로 바꿔 적용하지 않았다.

## 추가 인계와 카메라 기반 무작위 집기

같은 인계 수집기로 seed 10–15를 추가 실행해 6/6회 검증을 통과했다.
인계 데이터는 총 16회·34,159프레임이다. 위 인계 실험의 XY ±1mm 범위는 그대로다.

별도로 pgripper_vision_pick.py에서 블록을 x=0.175–0.230m,
y=−0.055–0.055m, yaw=±8° 범위로 무작위 배치하고 영상으로 찾아 집었다.
MuJoCo에서 추출한 같은 PGripper·상부 RGB-D·좌우 손목 카메라 위치와 FOV를 사용한다.
상부 원본 영상에서는 왼팔이 위쪽, 오른팔이 아래쪽에 보인다.

상부 RGB의 빨간색 영역과 metric depth로 4cm 블록 윗면 중심·회전각을 찾는다.
움직이는 팔의 손목 RGB에서 알려진 큐브 실루엣을 맞춰 XY를 보정하고,
영상에서 구한 블록 면에 손가락 방향을 맞추는 5자유도 IK로 접근한다.
왼팔 실험에는 왼쪽 손목, 오른팔 실험에는 오른쪽 손목 영상을 제어에 사용하며
매 실험 세 카메라를 모두 기록한다. 두 손목 영상을 동시에 융합하는 방식은 아니다.
블록 정답 좌표는 초기 장면 배치·기록·성공 판정에만 사용하고 IK 목표에는 넘기지 않는다.

| 최종 코드로 직접 실행한 검사 | 결과 |
| --- | --- |
| 왼팔 seed 101·103·105 / 오른팔 seed 102·104·106 | 6/6 집기·3초 유지 및 저장 검사 통과 |
| 관측 / RGB / 물리 시간 | 3,203프레임 / 9,609장 / 127.984초 |
| 유지 중 최소 블록 중심 높이 | 90.149mm 이상, 테이블 기준 |
| 최대 패드 법선 힘 / 관통 / jaw 연동 오차 | 2.736N / 0.0315mm / 0.0669mm |
| 상부 RGB 차단 | 0.5초, 접근 전 인식 실패로 종료 코드 2 |
| 오른쪽 손목 RGB 차단 | 5.85초, 접근 후 내려가기 전 종료 코드 2 |
| 기존 인계 검증기 회귀 확인 | 추가 seed 10 전체 데이터 재검사 통과 |
| MuJoCo TCP 재추출 | 저장된 양손 TCP와 정확히 일치 |

초기 시도에서는 수직 접근축만 맞춰 블록 모서리에 패드가 먼저 닿았다.
오른팔 seed 102는 힘 제한, 왼팔 seed 103은 jaw 연동 제한으로 중단됐다.
블록 회전각에 맞춰 손가락을 정렬한 뒤 같은 두 seed를 다시 실행해 통과했다.
이 실패 기록은 보존하고 최종 6회에는 포함하지 않는다. 힘·관통 제한은 완화하지 않았다.

다음 명령은 위 export에서 생성한 reference/vision_tcp.json도 필요하다.

```bash
"$SAPIEN_PY" -B 2ARM_ROBOT/robotwin/pgripper_vision_pick.py \
  --reference "$OUTPUT/reference" --runtime "$ROBOTWIN_RUNTIME" \
  --output "$OUTPUT/vision-left-101" --arm left --seed 101
"$SAPIEN_PY" -B 2ARM_ROBOT/robotwin/validate_pgripper.py "$OUTPUT/vision-left-101"
```

오른팔은 --arm right와 새 출력 경로를 지정한다.
--blank-top 또는 --blank-wrist를 붙인 대조 실행은 성공하면 안 되며 종료 코드 2가 정상이다.
출력은 기존 HDF5 계약과 source 사본·report.json·관측 시점 JPEG·상부 depth NPY다.

이 6회는 인계·내려놓기 없이 각 팔이 독립적으로 찾고 집어 유지하는 SIM 실험이다.
알려진 빨간색 4cm 큐브의 RGB-D/손목 RGB + IK + 접촉 규칙이며 학습한 IL 정책은 아니다.
가림·조명 변화·다른 물체·전체 작업 공간의 성공률과 실물 카메라 보정은 아직 확인하지 못했다.
