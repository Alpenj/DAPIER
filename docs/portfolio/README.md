## 먼저 확인할 내용

DAPIER는 Physical AI 수업과 개인 실습, 팀 프로젝트를 모은 개발 저장소입니다. 핵심은 코드 양보다 관측·행동의 계약, 실패 조건, 안전한 실행 경계와 재현 가능한 기록입니다. 이 저장소는 2026-09-05 확인 기준 비공개이므로 외부 검토에는 별도 접근 권한 또는 검토를 거친 공개 자료가 필요합니다.

[포트폴리오](https://julianjeonresume.netlify.app/)는 경력과 프로젝트를 소개하고, 이 저장소는 구현과 실험 이력을 제공합니다. [공개 학습 글](https://github.com/Alpenj/physical-ai-lab)은 개념과 다음 실험 질문을 설명합니다. 어느 한 자료가 다른 자료의 미검증 성능을 대신 증명하지 않습니다.

## 기여를 확인하는 방법

팀 과제의 목표, 개인이 수정한 파일, 참고한 외부 구현과 자산, AI 도움, 실제 수행한 검증을 나누어 읽습니다. `2ARM_ROBOT`는 팀 프로젝트이므로 기능 목록 전체를 개인의 단독 작성량으로 보지 않습니다. 파일 소유나 commit 수만으로 역할 비율을 수치화하지 않습니다.

프로젝트 설명에는 다음 근거가 함께 있어야 합니다.

| 항목 | 확인할 자료 |
|---|---|
| 문제·범위 | 프로젝트 README와 요구사항 원장 |
| 담당 변경 | PR, diff와 commit, 설계·인수인계 기록 |
| 구현 경계 | 직접 작성한 모듈과 외부 overlay·patch·모델 출처 |
| 검증 | 환경, 입력, 명령, artifact, 기대값·측정값 |
| 실패와 후속 작업 | 중단 원인, 제외 데이터, 미달한 gate, 다음 실험 |

아직 근거가 없는 역할 비율, 실물 성공률, 성능 개선율은 적지 않습니다.

## 공개 자료를 준비할 때

DAPIER 전체를 바로 공개하기보다, 평가에 필요한 코드·합성 예제·비식별 결과·환경 안내를 선별한 공개용 자료가 우선입니다. 실제 공개 전에는 추적 파일뿐 아니라 Git 이력, 장치 식별자·calibration, 데이터와 영상의 권리·개인정보, 외부 코드·자산의 이용 조건을 확인해야 합니다. 이 문서는 공개 설정 변경을 승인하거나 보안 감사를 완료한 문서가 아닙니다.

외부 검토자가 재현하지 못하는 실험은 명령만 나열하지 말고 입력의 공개 가능 여부, 환경과 제한, 공개 대체 fixture를 함께 안내합니다. 라이선스는 원저작물 권리와 사용자 결정을 확인한 뒤 별도로 정합니다.
